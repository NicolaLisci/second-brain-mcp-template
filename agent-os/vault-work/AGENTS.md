# Agent instructions

## Repository purpose

This repository is a work knowledge-management system. Treat it as confidential by default: it may hold employer, client and colleague information. Markdown notes are the source of truth. Do not treat it as a generic document dump.

## Core principles

- Preserve existing knowledge and prefer small, focused notes.
- Search existing notes before creating a new concept; avoid duplicates.
- Link related notes with Obsidian `[[wikilinks]]`.
- Distinguish facts, interpretations, ideas, decisions, and actions.
- Retain original sources and never invent citations or sources.
- Avoid unnecessary large-scale reorganization and favor useful knowledge over exhaustive capture.

## Inbox behavior

When processing Inbox, understand the capture, classify it as Project, Area, Resource, or Archive, identify reusable concepts, suggest or create links to existing notes, and preserve source information. Do not delete captured material without explicit permission.

## Distillation

Separate Source, Fact, Interpretation, Idea, Decision, and Action where useful. Never present AI-generated interpretation as fact.

## Atomic notes

Prefer one durable idea per knowledge note when useful, without creating artificially tiny notes for every sentence.

## Projects and MOCs

Project notes should record the outcome, why it matters, current state, next action, decisions, and relevant knowledge. MOCs are curated conceptual maps, not folder replacements.

## Knowledge transfer boundary

Knowledge may move from Work to Personal only after transformation into generalized, non-confidential professional learning. Do not copy company names, proprietary details, confidential data, code, customer data, or internal identifiers. When uncertain, keep the material in Work.

Never automatically copy work material into the Personal repository.

## Safety

Never automatically delete large numbers of notes, overwrite important material without checking, move entire directory trees without reason, fabricate sources, silently alter quoted material, or expose private repository content externally. Ask for approval before destructive or large structural changes.
